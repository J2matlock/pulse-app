# Phase 2 — "It just works" (approved by the owner 2026-10-14; starts after Phase 1 is merged and pushed)

Goal: an Apple-like "it just works" feel. Phase 1 removed friction; Phase 2 makes the app decide more on the user's behalf and ask less, and makes it feel fast, consistent and finished. Same constraints as Phase 1 unless a plan says otherwise and the reason is logged in CLAUDE.md's Decision Log: no database migrations unless a plan proves one is unavoidable (then use the /new-migration skill and its guards), no new network calls, vocabulary layer, 15 px / 44 px / 3 px, `npm run gate` green before every commit.

## The ten ideas
1. **Ask fewer questions, make better guesses.** (a) Import that just works: combine names, recognise date columns, guess repeats ("Last visit" → monthly, "Annual review" → yearly), apply rules so colours appear, then ONE summary screen ("We set up 80 clients. Last Visit repeats monthly; Annual Review yearly. Change anything?") instead of several steps. (b) Features that turn themselves on when needed: when the user searches Help for a feature that is off, or makes a 30-day rule on a "contact"/"visit" column, offer the matching feature in one click ("Want Pulse to track how many contacts each client gets per month?"). (c) Fewer settings: audit every setting; if one value is right for ~95% of users, remove the option or move it under an "Advanced" disclosure.
2. **One obvious next step on every screen.** Each screen has one primary action and one sentence saying what it's for. Dashboard opens with the next thing to do ("3 visits overdue. Start with Maria Garcia →"). On a profile with an overdue contact, the note box is open with the matching kind selected.
3. **Change things where you see them.** One shared "deadline card" popover (due date, words, Done, Done on…, Extend) used identically on grid cells, profile, calendar and dashboard. Click a column name to rename in place with the menu below. Resize by dragging, double-click to fit, instant.
4. **Undo as the safety net instead of confirmations.** Replace "Are you sure?" dialogs for reversible actions (trash, archive, delete a task/checklist item/rule that has undo, move) with doing it plus an "Undo" toast (~8 s). Keep typed confirmations only for truly irreversible actions (Empty Trash, erase everything, restore over current data).
5. **Consistency as a system.** Shared components that enforce the style guide (`PrimaryButton`, `SecondaryButton`, `DangerButton`, `EmptyState`, `Confirm`, `RowMenu`, `Toggle`, `Dialog` with pinned footer); migrate call sites; a small design-token set (≈5 spacing values, 3 text sizes, 1 radius, 1 accent colour) and a lint/test that flags off-system values in new code.
6. **Motion and feedback that explain what happened.** Done → row slides out and counters tick; new column/row slides in and highlights; archive shrinks away; 150–200 ms, honour reduced-motion (the `motion` library is installed). Every click acknowledged within ~100 ms (pressed state, spinner after 300 ms).
7. **The first five minutes feel finished.** Replace the 7-step first-run tour with (a) a single "here's your caseload" moment: sample list with one overdue row pulsing and one hint ("Red means overdue. Click Done when you've seen them.") and (b) small one-time hints shown the first time the user reaches each screen (stored in settings; never repeat; "Retake the tour" stays in Help).
8. **Visual polish that reads as quality.** More whitespace, fewer card borders (group by spacing; the grid keeps its chunky lines on purpose); one accent colour for actions, deadline colours only for status (remove violet/teal/amber buttons competing); designed empty states (icon + one sentence + one action); intentional app icon, window title and About screen.
9. **Speed you can feel.** Measure first (`npm run perf`, plus renderer timings): profile open from grid, dialog open, search result, grid scroll at 500+ rows. Targets: profile < 150 ms, dialogs instant, 60 fps scroll. Preload the next likely screen (hovered row's profile data), memoise hot renders.
10. **Test with real people.** Not agent-implementable. Write `plans/usability-test-kit.md`: a 15-minute unmoderated-observation script for 2 care coordinators with a fresh install (tasks, what to watch for, what not to say, a one-page notes sheet), and a short checklist to run after every release. Hand it to the owner.
