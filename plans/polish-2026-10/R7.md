# R7: Code hygiene across src/

Scope: dead code, duplicated or diverged helpers, TODO/console leftovers, exhaustive-deps warnings, hard-coded vocabulary outside the eslint rule, sub-15px text, unused IPC channels.

There are no TODO, FIXME or `console.*` leftovers in src/. Every IPC channel that the renderer calls has a handler, and every push event has a listener.

## Bugs

- **[bug]** `src/renderer/components/contacts/ContactForm.tsx:122` (deps at :200): stale closure. `handleSave` is a `useCallback` whose deps leave out `customValues`, so it keeps the `customValues` from the last time `form` changed. On a new contact, typing the name and then filling in the custom fields means the save loop at :169 sees `{}`, and the custom values are silently lost. On an existing contact, the values loaded at :103 and any edits made after the last change to a regular field are lost too. Also, `dirty` (:108) ignores `customValues`, so Esc after editing only a custom field closes without the discard prompt. Fix: add `customValues` (and `t`) to the deps, and include `customValues` in the dirty check.
- **[bug]** `src/renderer/views/DashboardView.tsx:159` and `:190`, `src/renderer/views/TasksView.tsx:113` with `src/renderer/stores/taskStore.ts:42`, `src/renderer/views/FocusModeView.tsx:95`: the load-error banners can never show. `safeInvoke` never throws, and `taskStore.loadTasks` swallows its errors, so the `catch` that sets `loadError` never runs. A failed `DASHBOARD_GET_ALL` only gets logged, and the dashboard shows "Nothing overdue — Great work, you're all caught up!", which is wrong data in a deadline tracker. Tasks and Focus Mode do the same thing with their empty states. Fix: call `setLoadError(...)` when `!res.ok` (and have `loadTasks` return or record a failure), not only in `catch`.
- **[bug]** `src/renderer/views/ProfileView.tsx:195`: `clientName` is only the name-column cell. The profile header (`ProfileHeader.tsx:301`) uses `getClientName()`, which adds the last name and uses the list's display format. So the header says "Jane Smith" (or "2019 Honda Civic"), while "Archive Jane?", "Move Jane to the Trash?", the print layout, the PDF file name, recent records, the letter dialog and the note composer's `{client_name}` all say "Jane", or the bare name cell. An empty name cell gives `''`, not `null`, so the title becomes "Archive ?". Fix: compute `knownName` with `getClientName(row, columns, '')`.
- **[bug]** `src/renderer/components/grid/DataGrid.tsx:671` with `src/renderer/components/layout/TopBar.tsx:89`: the "Added — your filter would hide it → Show all" toast sets `searchQuery: ''` directly. The TopBar search box only copies the store value when the list changes, so it still shows "smith" while the list shows every record. The next keystroke silently brings back the old search plus the new letter. Fix: have TopBar sync `inputValue` whenever the store's `searchQuery` differs from it while no edit is pending, or route "Show all" through an action TopBar subscribes to.
- **[visible]** `src/main/export-pdf.ts:367` and `:386`: checklist due dates in a profile PDF are hard-coded `formatDate(item.due_date, 'us')`. The cells in the same PDF follow Settings → Date format (X-20), so a DD/MM user gets both formats mixed on one page. Fix: use `formatCellValue(item.due_date, 'date')`, or `formatDate(..., savedDateFormat())`.
- **[visible]** `src/renderer/components/settings/DataSection.tsx:249`: the toast reads "Compacted: 42 records removed." In a workspace where records are clients, that sounds like 42 clients were deleted, and "Compacted" is jargon. Fix: say something like `Removed ${n} old edit-history entries.`

## Platform and vocabulary leaks (things the eslint rule misses)

- **[visible]** `src/renderer/components/layout/TopBar.tsx:182-241`, `Sidebar.tsx:442,475,625,663,808,866`, `views/TasksView.tsx:471`, `settings/SecuritySection.tsx:130`, `contacts/ContactForm.tsx:248`, `views/help/faqData.tsx:201,356,378,514-543`: tooltips, aria-labels and help text hard-code "Ctrl+…".   - `components/contacts/ContactFilterBar.tsx:130` "Sort contacts"
  - `ContactImportExport.tsx:262,331,332` "…contacts for import"
  - `profile/NoteFiles.tsx:19` "Attach a file to this note"
  - `profile/CaseLogEntry.tsx:246` "Reason for voiding this note"
  - `settings/ActivityTypesEditor.tsx:74,157`
  - `settings/MeasuresEditor.tsx:66`
  - `settings/WorkspaceSection.tsx:28` "no records or notes"

  Fix: switch these to `t()`/`f()`. Optionally add record/note/contact to a second rule that runs on `title`/`aria-label` and on `toast` call arguments.
