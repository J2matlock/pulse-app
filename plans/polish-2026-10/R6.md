# R6: main process review

Area: `src/main/**`, which covers IPC handlers, migrations 044–047, the deadline engine, list and column trash, sample rows, contacts and templates.

- **[bug]** `src/main/note-date-updates.ts:58`: `applyNoteDateUpdates` only looks at `column_type = 'date'`. The column menu still offers "Update from notes" on Deadline columns (`ColumnHeader.tsx:620` uses `takesDeadlineRule`, which includes `'deadline'`). Migration 046 and `convertDateColumnsToDeadline` (in `ALERT_RULE_UPDATE`) also turn Date columns into Deadline columns without touching their `note_updates`. Example: "Monthly visit" follows Visit notes and has an "on fixed dates" rule. After 046 it is a Deadline column, logging a Visit no longer moves it, and nothing tells the user. Settings → note types still says the type updates that column (`activity-types.ts:118`). Fix: match `column_type IN ('date','deadline')` in the `note_update_cols` query.

- **[bug]** `src/main/stages.ts:61` and `src/main/stages.ts:126` (plus `StageSettingsDialog.tsx:37`): a stage's "fill in today's date" only accepts Date columns. Once its column becomes a Deadline column (046, or after a rule edit), two things break. Entering the stage silently stops stamping the date. Saving any change to that column's stage settings also fails with "The date to fill in … must be a date column of this list". A stage that stamps "Intake done" is exactly the kind of done-date column E1 converts. Fix: accept `'deadline'` in both checks and in the dialog's `dateColumns` filter.

- **[bug]** `src/main/sample-marks.ts:12` / `src/main/sample-data.ts:93`: a sample row's fingerprint is built from every `column_id:value` pair. The following list-level actions change every sample row's fingerprint, even though the user touched no entry:
  - deleting a column from the sample list (its cells cascade away)
  - changing a column's type, which converts the values
  - renaming dropdown options with "update records"

  "Remove sample data" then treats every entry as user-edited. It keeps all of them as real entries and renames the list "My Clients". Fix: when comparing, build the fingerprint only from columns that still exist and still have their original type. Alternatively, store per-column values and ignore columns that are gone. Changes made through `COLUMN_SET_OPTIONS` / `COLUMN_CHANGE_TYPE` should not count as edits.

- **[bug]** `src/main/appointments.ts:543`: `appointmentsNeedingOutcome` (the morning-briefing count "past appointments without an outcome") only excludes trashed records. The Calendar hides scheduled appointments of archived records and of lists in the Trash (`OPEN_RECORD_SQL`). Archiving only cancels appointments from today on (`upcomingIds`). So after archiving a client with an unresolved visit last week, the briefing keeps counting it for 14 days and the user can't find it anywhere. Fix: join grids and use `OPEN_RECORD_SQL` in this count, or have archiving also handle past scheduled appointments.

- **[bug]** `src/main/ipc/ipc-row.ts:122` / `src/main/ipc/ipc-row.ts:452`: moving a record to another list remaps `cells`, `cell_history` and parked values. It does not remap `deadline_done` (new in 046), `deadline_progress` or `deadline_extensions`, which stay keyed to the old list's column id. Example: a one-off "Background check" marked Finished moves to a list that has the same column. It shows as overdue again, its finished steps disappear, and so does its extension. Fix: inside the move transaction, update those three tables' `column_id` for columns that map by name (as `updateHist` does).

- **[bug]** `src/main/list-trash.ts:133`: `trashList` reads `is_active` but never checks it. Deleting a list that is already in the Trash (for example a double click on the confirm button, or a second window) overwrites `deleted_snapshot` with an empty snapshot, because its links are already gone. It also resets `deleted_at`, so a later restore loses every link to other lists. Fix: return early (or throw a `TrashError`) when `grid.is_active === 0`.

- **[visible]** `src/main/ipc/ipc-cell.ts:138`, `src/main/placeholders.ts:30`, `src/main/export-forms.ts:45` and `:115`, `src/main/forms.ts:91`: Deadline columns are handled as plain text in four places:
  - "Record every change" timeline entries read `Annual Review changed to "2026-10-12"` (ISO, quoted) instead of the date sentence.
  - `{{field:X}}` in letters prints the ISO date.
  - Printed forms show the ISO date, and an empty Deadline column gets a blank line instead of the `__ / __ / ____` date line.
  - Submitted forms skip date validation.

  Columns that 046 converted (sample "Annual Review" has `log_changes: true`) show this right away. Fix: treat `'deadline'` like `'date'` in each of these branches.

- **[visible]** `src/main/contacts.ts:371`: a contact's linked-records list (`client_links_by_provider`) filters archived and trashed records but not lists in the Trash. Records of a deleted list still appear under the contact, and opening one lands on a record whose list is gone. Fix: `JOIN grids g ON g.id = r.grid_id AND g.is_active = 1` (and drop the `LEFT JOIN` on `pcl.grid_id`).

- **[polish]** `src/shared/ipc-contract.ts:286-295`: the case-log contract no longer matches the handlers:
  - `case-log:delete`, `:void`, `:unvoid` and `:restore` are typed `true`, but they return `{ reverted_dates }` / `{ updated_dates }`.
  - `case-log:create` returns `updated_dates`.
  - `case-log:get-edits` also returns `occurred_at`.
  - `case-log:set-occurred` is missing.

  `CaseLog.tsx:69` works around this with casts. Fix: update the return types (`CreatedCaseLogEntry`, `{ reverted_dates: NoteDateRevert[] }`, and so on) and drop the casts.

- **[polish]** `src/main/ipc/ipc-checklists.ts:345` and `:376`: `CL_TEMPLATE_EXPORT` writes, and `CL_TEMPLATE_IMPORT` reads, a renderer-supplied `filePath` with only an extension check. They never call `assertSafePath`, which every other file-path handler uses. Fix: call `assertSafePath(filePath)` (wrapped to return a plain-language `fail`) in both.
