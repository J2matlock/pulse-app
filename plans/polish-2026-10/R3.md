# R3: record page, notes, tasks, calendar, forms, files, links, focus mode, snippets

Read-only review, 2026-10-11. Every item below was traced through the code end to end.

## Bugs

- **[bug]** `src/renderer/views/ProfileView.tsx:127-135` (with `:157-179`): **the record page can loop between two lists forever.** The `?gridId=` effect calls `loadGrid(target)` every time `activeGridId` differs from the URL's list. The lookup effect does the opposite: when the record isn't in that list, it calls `loadGrid(loc.gridId)`, which changes `activeGridId`, so the first effect loads the URL's list again, and so on. Two ways to hit it:
  - Open a record from **Recent** (TopBar stores the gridId at the time of the visit) after it was moved to another list, for example from "Waitlist" to "Active".
  - Open a record from the Dashboard or Calendar (all of these add `?gridId=`), then use More ▾ → "Move to another list…".

  The page stays on "Loading…" and `GRID_GET_FULL` keeps firing. Fix: apply `?gridId` once per rowId (keep it in a ref), and let the lookup result win after that. Or drop the param from the URL once it has been used.

- **[bug]** `src/renderer/views/ProfileView.tsx:165,176`: **a record that is active in the current list but missing from the loaded rows shows "We couldn't find this record. It may have been deleted."** The lookup reloads only when `loc.gridId !== activeGridId`. For the same list it stores `'missing'`. This is the same stale-store problem the user hit. Concrete path: a link type within one list (allowed, `links.ts:70`), then Linked → "New" (`LinkedRecords.tsx:99` → `linkActions.ts:57`). That creates a record in the active list without refreshing `gridStore.rows`. Clicking the new name then says it was deleted, and Prev/Next skips it. Fix: when ROW_LOCATE says `active` in the active list but the row isn't in `rows`, call `loadGrid` once before giving up. Also refresh the grid after `createAndLink` when the other list is the active one.

- **[bug]** `src/renderer/views/FocusModeView.tsx:321`, also `src/renderer/views/dashboard/TaskRow.tsx:59`: **Undo after "Done" on a task in Focus Mode or on the Dashboard always fails.** It calls `mustInvoke(IPC.TASK_RESTORE, taskId)` with a number. `TASK_RESTORE` expects a full task object and returns "Invalid task format", so `mustInvoke` throws. On top of that, `taskStore.completeTask` already pushes its own correct undo step (TASK_UNCOMPLETE) when the task is loaded, so one click puts two undo entries on the stack. Fix: drop the extra pushWithToast and let `completeTask` push the toast version. It already restores `due_date` and history through TASK_UNCOMPLETE.

- **[bug]** `src/renderer/views/TasksView.tsx:155-163`, `src/renderer/views/FocusModeView.tsx:287-296` and `:343-358`, also `dashboard/ChecklistDueRow.tsx:63-67`: **undo and redo of a checklist tick done outside the record page are wrong.**
  - For a repeating item, main moves it straight to its next due date (1.26). Undo then sends only `{is_completed: 0, completed_at: null}`, so the due date stays moved on.
  - Redo isn't `silent`, so main treats it as a fresh completion: it writes another "Completed checklist item" note and advances the date a second cycle.
  - Undo on a one-off item writes a "Reopened checklist item" note, which is the clutter 3.17 removed on the record page.
  - The Focus Mode "due" list (`:343`) never captures `sysLogId`, so its completion note survives undo.

  Fix: copy `Checklist.tsx:203-235`. Use the `repeat` field from the response for before/after states, pass `{ silent: true }` on undo and redo, and add the `void_case_log` side effect.

- **[bug]** `src/renderer/views/TasksView.tsx:264-271`, `:312-326` and `:434-443`: **task group undo and redo use ids that no longer exist.**
  - Add group: redo creates a new group with a new id, so a later undo deletes the old id and does nothing.
  - Delete group: undo recreates the group under a new id, so redo deletes the old id and the group stays.
  - Apply template into a new group: undo deletes the tasks and the group. Redo re-applies with the deleted `groupId` (there's no FK on `group_id`), so the new tasks point at a missing group. In grouped mode they then appear nowhere, because only `null` and existing group ids are rendered. The `createdIds` used by undo are also never updated after redo.

  Fix: keep the current id in a `let` that redo updates (like `createAndLink` does), and have redo recreate the group too.

- **[bug]** `src/renderer/views/ProfileView.tsx:277-283` and `:581-593`: **archiving from the record page leaves upcoming appointments on the calendar.** The record page's More ▾ → Archive (3.6) calls `archiveRow(rowId, reason)` without `cancelAppointments`. Its dialog also has no "Cancel the N upcoming appointments" box. The grid's `ArchiveDialog` (`GridDialogs.tsx:63-67`) and `HandoffDialog.tsx:60` both offer it (1.13). This is a seam between two tracks. Fix: reuse `useUpcomingAppointments` and `CancelAppointmentsCheckbox` here (or `ArchiveDialog` itself).

- **[bug]** `src/renderer/components/forms/FormFillHost.tsx:25-34` (button at `ProfileView.tsx:489`): **on an archived record, the "Fill in a form" buttons do nothing.** When the form's list is the active one, the host looks for the row in `grid.rows`. Archived rows aren't there unless Show archived is on, so `if (rowId !== undefined && !row) return` exits silently. Fix: fall back to `ROW_GET` when the row isn't loaded, or hide the forms row for archived records. Either way, show a toast instead of failing silently.

- **[bug]** `src/renderer/views/CalendarView.tsx:98,151-152` (and `src/main/calendar.ts:31-36`): **with the Tasks feature switched off, the calendar still shows "Task: …" items.** `offered` hides the Tasks toggle, but `layers` defaults to (and keeps) `tasks`, and `CALENDAR_ITEMS` always returns tasks. The user can't turn them off, and clicking one goes to `/tasks`. Fix: build `byDay` from `layers ∩ offered`, the same way appointments drop out when that feature is off.

- **[bug]** `src/renderer/components/profile/RecordLetterDialog.tsx:64`: **"Note it on the case log" logs the letter as the user note type `'note'`.**
  - If that type has been archived, or an example workspace replaced it (`activity-types.ts:189`), `CASE_LOG_CREATE` rejects it and the user gets "We couldn't note the letter…".
  - When it does work, it's a real user note. So it moves date columns that follow Note (`applyNoteDateUpdates`), counts toward note-type requirements, and could be counted as a contact made.

  Fix: log it as a system entry (`'system'`, or a dedicated system type), so it neither counts nor moves dates.

## Visible

- **[visible]** `src/renderer/components/profile/CaseLogEntry.tsx:106` (with `src/main/ipc/ipc-caselog.ts:219,245,276`): **notes show "edited" when nobody edited them.** The label is `updated_at !== created_at`. Completing or un-completing a follow-up, and restoring a note (undo of delete), all set `updated_at = datetime('now')`. So a note shows "edited", with the tooltip "Edited <time>", after you only ticked its follow-up. `SET_MEASURES` deliberately leaves `updated_at` alone for exactly this reason. Fix: base the label on `edited_at`, which only text and day edits set.

- **[visible]** `src/renderer/components/tasks/TaskItem.tsx:360` (also `:251,265,295`) and `src/renderer/views/SnippetsView.tsx:334`: **row actions can't be seen from the keyboard.**
  - Tasks: Snooze, Edit and Delete sit in `opacity-0 group-hover:opacity-100`, and so do "Add date", "+ Priority" and "Repeat".
  - Snippets: Edit, Delete and the confirm-delete buttons have the same classes.

  With no `group-focus-within`, tabbing onto them focuses an invisible button, so the 3px focus ring can't be seen either. On Snippets, a pending "Delete" confirm also vanishes when the mouse leaves. Fix: add `group-focus-within:opacity-100` (as `CompletedTaskItem` does with `focus-visible:opacity-100`).

- **[visible]** `src/renderer/components/tasks/TaskItem.tsx:353`: **the snoozed badge reads "Snoozed until 2026-10-14 ×".** It shows the raw stored date. S-13 asked for "Tomorrow (Sun, Oct 11)" style, and `SnoozeDialog.tsx:6` already has `snoozeDay()`. Fix: format it with `snoozeDay` or `dueDateLabel`.

- **[visible]** `src/renderer/views/focus-mode/ClientFocusItem.tsx:36`, `FollowUpFocusItem.tsx:26`: **a long name in Focus Mode runs across the Done button.** The name is a `truncate` on an inline-block `<button>`. With `nowrap`, the button grows to the full text width instead of the column width, and since the parent doesn't clip, a long name paints over the Done/Renew button. This is the same class of overlap as the grid cell bug. Fix: add `block max-w-full` (or `w-full`) to the button so `truncate` takes effect, and add `title={name}`.

## Polish

- **[polish]** `src/renderer/components/profile/CaseLogEditHistory.tsx:20`: **earlier versions are fetched once and never refreshed.** `if (versions) return`. The entry stays mounted across reloads (it's keyed by id), so after a second edit, reopening "show earlier versions" still lists the old set. Fix: reset `versions` when `editedAt` changes, or key the component on `editedAt`.

- **[polish]** `src/renderer/components/profile/CaseLogEntry.tsx:246,285,329` and `CaseLog.tsx:503,666`: **"note" is hard-coded in the note UI.** Examples: "Reason for voiding this note", "Notes older than 30 minutes can't be deleted…", "A note can't be empty", "We couldn't void that note", "Saved as one note with these headings". Everything around them says `t('activity')` (for example "case note"). The eslint rule only catches "case note(s)", which is why these slipped through. Fix: use `t('activity')`.

- **[polish]** `src/renderer/components/profile/RecordAppointments.tsx:33` (with `src/main/appointments.ts:70`): **the section counts are capped.** The section shows at most the next 5 and the last 5, so the title count tops out at "Appointments (10)" and "5 coming up", even for a weekly series or a long history. Fix: return real counts from main, or label the count "next 5".

- **[polish]** `src/renderer/views/tasks/SnoozeDialog.tsx:44`: **the custom snooze date allows today.** `min={today}` lets you pick today, but `isSnoozed` is `> today`, so "Snooze" quietly does nothing. Fix: `min={localDateFromToday(1)}`.

- **[polish]** `src/renderer/views/TasksView.tsx:466,546`: **two small leftovers on the Tasks page.**
  - The header count says "· 2 urgent" from checklist items even when the Checklists feature is off and that section is hidden.
  - The empty-state `<kbd>` uses `text-xs` (12px), which is under the 15px rule.
