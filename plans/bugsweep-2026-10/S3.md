# S3: Grid data integrity

Read-only review, 2026-10-11. Scope: cell editing and type rules, paste, bulk edit, Delete, undo/redo, column add/rename/retype/reorder/hide/delete/restore, sorting and filtering by type, Find & Replace, duplicate, and move/copy to another list. I read every item below end to end in the code.

## Bugs

- **[bug]** `src/renderer/stores/gridStore.ts:388` and `:534`, with `src/main/ipc/ipc-row.ts:318`. Undo for "Added new record" and "Duplicated" uses `ROW_HARD_DELETE`, which refuses any row older than 60 seconds. To reproduce: add a record, type into it for a minute, undo the typing, then press Ctrl+Z once more. The toast says "Undo didn't work: Hard delete only allowed for recently-created rows" (the message is jargon too; `failureText` in `undoStore.ts:91` doesn't run it through `friendlyError`). Because a failed undo goes back on top of the stack, every later Ctrl+Z hits the same step, and nothing older can be undone (`undoTo` stops there as well). **Fix:** after the window, undo by soft-deleting (`ROW_DELETE`, with redo as `ROW_RESTORE_DELETED`), or always do that. Run undo/redo failure text through `friendlyError`.

- **[bug]** `src/renderer/stores/gridStore.ts:392` and `:539`, `src/renderer/stores/gridColumnSlice.ts:103`. Redo of an add record, duplicate or add column creates a new row or column with a new id. Cell edits made in it are still on the redo stack, keyed to the old id. To reproduce: add a record and type a name, undo twice, then redo twice. The second redo fails with "…the record or column no longer exists. Try reloading the grid." and stays on top of the redo stack, so the typed values can't be brought back and every later redo is blocked. The same happens with a new column. **Fix:** make undo reversible by id: soft-delete and restore the row, and restore the column with `COLUMN_RESTORE deletedId`, which keeps the id. Then redo brings back the same row or column instead of making a new one.

- **[bug]** `src/main/column-options.ts:78-83`. Renamed choices are applied one after another, and each rename queries the cells again. Swapping two choices (Priority "High" ↔ "Low", with "Also change N records" ticked) first turns every High into Low, then turns every Low (old and new) into High. Every record ends up "High". A chain (A→B and B→C) merges A and B the same way. Undo sends the reversed map and merges them again. **Fix:** read the row ids for every `from` value before writing anything, then apply the renames to those fixed sets.

- **[bug]** `src/renderer/components/grid/ColumnHeader.tsx:128-129`, `src/renderer/components/grid/GridToolbar.tsx:713` (also reached from Add Column → "more" at `:240`), and `src/renderer/stores/gridColumnSlice.ts:122-131`. Choosing a done-date rule for a Date column (Decision E1) calls `updateColumn({ config, column_type: 'deadline' })`. The old type-change guard catches that and parks it behind GridView's "Change column type? … The values stay as they are" dialog. Meanwhile ColumnHeader shows "is now a Deadline column" at once, before anyone confirms. If the person cancels that unexpected dialog, the rule isn't attached at all. From the Add Column flow, the rule they just created is left attached to nothing. **Fix:** let these E1 conversions bypass the pending-confirm path (call `COLUMN_UPDATE` directly, or add a `skipConfirm` option). Show the toast only after the change is saved.

- **[bug]** `src/main/list-trash.ts:109-110` with `src/main/ipc/ipc-grid.ts:313-319`. Deleting the name column hands the name role to another column. Undo (`COLUMN_RESTORE`) brings the column back with `is_name_column = 0`, because the list "has a name column now". After Delete "Name" → Undo, every record is still named by the stand-in column (for example the phone number) on the dashboard, in search and in links. Also, the stand-in is chosen with `ORDER BY (column_type = 'text') DESC, position` and no `canNameRecords` check. In a list with no other text column it can be a checkbox, notes, deadline or link column. **Fix:** when the snapshot was the name column, take the role back on restore (clear it from the stand-in) and refresh the display names. Choose the stand-in only among `canNameRecords` types.

- **[bug]** `src/main/ipc/ipc-row.ts:32` (`tgtMap` by lowercase name), `:139-142` (move) and `:49` (copy). Columns can share a name. Nothing checks this in `COLUMN_CREATE`, rename or import, and there's no UNIQUE index. If the source list has "Phone" and "phone", both cells are mapped to the target's one "Phone" column. Move does `UPDATE cells SET column_id` twice for the same row, and copy does two INSERTs. Either way UNIQUE(row_id, column_id) fails, the whole move or copy rolls back, and the dialog only says "Something went wrong. Please try again." **Fix:** when two source columns map to one target, carry the first and park (move) or skip (copy) the rest. Better still, refuse duplicate column names when columns are added or renamed.

- **[bug]** `src/renderer/utils/filterMatch.ts:94-101` and `:88-89`. Number and money filters use `parseFloat` on the typed value, and the value box is a plain text input (`FilterBar.tsx:454`). "Balance greater than 1,000" parses as 1, so records with 5 or 50 match. "greater than $100" parses as NaN, so nothing matches while the chip reads "greater than $100". "equals" compares strings, so 1200.5 typed doesn't match a stored "1200.50", and "$1,200" matches nothing. **Fix:** clean the filter value the way paste does (`replace(/[$,\s]/g, '')`) and compare numbers numerically for equals/not_equals on number and currency columns. Or give the value box `type="number"` for those columns.

- **[bug]** `src/renderer/utils/filterMatch.ts:55` and `:72-83`, `src/renderer/components/grid/DataGrid.tsx:230`, `src/renderer/components/grid/FilterBar.tsx:258,268`. Filters are matched against the visible `columns` only. `loadGrid` (`gridStore.ts:246-248`) keeps filters on hidden columns, and saved views often hide the column they filter on. With the column hidden:
  - a "due status is Overdue" filter on that column finds no target column, so every record disappears;
  - a checkbox "is unchecked" filter compares `''` with `'false'`, so blank checkboxes stop matching;
  - the chip reads "Col 57".

  Grouping by a hidden column (`useGridGrouping.ts:150`) also loses its option order, checkbox labels and link names. **Fix:** pass `[...columns, ...hiddenColumns]` to `matchFilter`, the grouping hook and the chip lookup.

- **[bug]** `src/renderer/components/grid/ChangeTypeDialog.tsx:22`. The name column can be changed to Checkbox or Notes, which `canNameRecords` says can't name records (the "Use as name" menu enforces this, but this dialog doesn't). Change "Name" to Checkbox: the preview says the names "stay as they are", but every name cell then draws as an unchecked box. One click on a box (`SortableRow.tsx:411-414`) writes "true" over the person's name, and that becomes their display name. **Fix:** for the name column, offer only `canNameRecords` types, or say "Choose another name column first".

## Visible

- **[visible]** `src/renderer/components/grid/gridSort.ts:12-17` and `src/renderer/components/grid/DataGrid.tsx:418-424,459-470`. Every comparator returns "blank after value", and TanStack (8.21.3) multiplies the result by −1 for descending. So a descending sort on a date, number, text, link or "Days until" column puts every empty cell at the top. Deadlines sorted descending start with done and paused. The priority (acuity) header's first click is descending, which lists every unassigned record above the high-priority ones (`a === -1 → 1`, then flipped). **Fix:** handle blanks outside the direction: set `sortUndefined: 'last'` and return `undefined` from the accessor for empty values, or check `sorting` direction inside the comparators so blanks always go last.

- **[visible]** `src/main/column-type.ts:41` and `:85`. `convertValue` only rewrites values into the new type's form. Values in the old type's stored form are left as they are. Tags → Text shows `["urgent","new"]` in every cell, while the preview said "All 40 values fit". Tags → Dropdown or Status makes choices literally named `["urgent"]`. Checkbox → Text or Dropdown shows or offers "true"/"false". **Fix:** first convert the old stored form to its text with `cellText(fromType, value)`, then into the new type. For Checkbox → text, "Yes"/"No" is clearer.

- **[visible]** `src/renderer/components/grid/gridHelpers.ts:54-57`. When one Excel or Sheets cell that contains a line break is copied, it reaches the clipboard quoted: `"line 1\nline 2"`. Pasting it into a text, phone or email column is refused as "several cells from a spreadsheet". Pasting it into Notes or Address stores the surrounding quotes, and any doubled `""` inside. **Fix:** if the whole body is one quoted field (`/^"([\s\S]*)"$/` with only doubled quotes inside), unquote it and un-double the quotes before checking for tabs and newlines.

## Polish

- **[polish]** `src/renderer/components/grid/gridHelpers.ts:24`. Paste reads dates month-first (`parseDate` defaults to `'mdy'`). Someone who set Settings → Date format to DD/MM/YYYY pastes "06/10/2026" from their own spreadsheet and gets June 10. **Fix:** pass `'dmy'` when the `date_format` setting is `eu`.

- **[polish]** `src/renderer/components/grid/ColumnHeader.tsx:109`, `DataGrid.tsx:642`, `src/main/ipc/ipc-grid.ts:470`. Reordering sends only the visible columns' ids, so main renumbers them 0…n−1 and the hidden columns keep their old positions. Those now collide with visible ones, and a hidden column shown again lands beside an unrelated column. **Fix:** include `hiddenColumns` in the ordered list, keeping their place relative to their neighbours, or have main renumber all columns of the list.

- **[polish]** `src/renderer/components/grid/MoveToGridModal.tsx:25` (callers pass `columns`; `GRID_GET` returns visible `columns`). The carry-over preview compares only visible columns. A value that will go into a hidden column of the same name in the target is listed as "won't show". A hidden source column's data, which is carried or parked, isn't mentioned at all. **Fix:** compare against `columns` plus `hiddenColumns` on both sides.

- **[polish]** `src/main/ipc/ipc-cell.ts:93` ("Try reloading the grid."), `src/main/ipc/ipc-row.ts:322` ("Hard delete only allowed for recently-created rows") and `src/main/ipc/ipc-grid.ts:318` ("Cannot delete the only column in this grid."). Developer words ("grid", "rows", "Hard delete") reach toasts through undo `failureText` and `deleteColumn` (`err.message`). **Fix:** reword them ("Reopen the list", "That can't be undone any more"), and make `failureText` use `friendlyError`.

- **[polish]** `src/renderer/stores/gridColumnSlice.ts:99`. Undoing "Added column" uses `COLUMN_DELETE`, which puts a copy in the list's "Deleted columns". Each add → undo leaves an entry in the Trash for 30 days, for a column the person thinks never happened. **Fix:** purge the Trash entry it just made (`COLUMN_PURGE` with the returned `deletedId`). Or keep it and make redo restore it, which also fixes the redo bug above.

- **[polish]** `src/renderer/components/grid/MoveToGridModal.tsx:111` (and the bulk modal at `:268`). "Copy to another list" pushes no undo step, unlike Move. Ctrl+Z then undoes whatever came before the copy instead. **Fix:** push an undo step that soft-deletes the new copy (`ROW_COPY_TO_GRID` returns its id).

- **[polish]** `src/renderer/components/grid/GridContextMenu.tsx:191`. The menu's "Clear cell" writes `''`, while Delete/Backspace writes `null`. The text comparator (`DataGrid.tsx:481-486`) only puts `null` last, so cells cleared from the menu sort to the top of an ascending sort, ahead of every name. **Fix:** write `null` from "Clear cell", and treat `''` as blank in the comparator.
