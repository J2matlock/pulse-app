# S1: Empty and first states

Read-only review of views/**, components/** and stores/**. I traced each item through the code.

- **[bug]** `src/renderer/components/contact-req/ContactRequirementsDialog.tsx:87,130`: a list with no requirements has no way to add its first one. "Add another" only shows when `drafts.length > 0`. The only other way in is the suggestion chips, and those are filtered down to types the workspace still has (visit/phone/meeting/email). After a starter like auto-service, fire-alarm-inspection or job-search, `replaceStartingTypes` archives those built-in types, so the dialog shows the intro text, nothing to click, and Save. The same dead end happens after removing the last requirement. **Fix:** show a plain "Add a requirement" button whenever `drafts !== null && drafts.length < 10`, and keep the suggestion chips as extras.

- **[bug]** `src/renderer/stores/contactsStore.ts:371` + `src/renderer/components/contacts/ContactFilterBar.tsx:162`: deleting the category that is the current filter leaves `filterParams.categoryId` pointing at a category that no longer exists. `deleteCategory` reloads with that filter, so the directory says "No contacts match your search". If it was the last category, the whole chip row (including "All") is hidden, and the "Active filters" row doesn't show category filters. That leaves no control to clear the filter. `filterParams` lives in the global store, so leaving the page doesn't reset it. **Fix:** in `deleteCategory`, drop `categoryId` from `filterParams` when it matches the deleted id, before reloading.

- **[bug]** `src/renderer/stores/contactsStore.ts:150-153`: the Undo step for "Created contact" deletes `created.id` and reloads the list, but leaves `selectedProviderId`/`selectedProvider` alone. Scenario: add a contact, click it, press Ctrl+Z. The right panel keeps showing the deleted contact, and editing, starring or logging against it fails. **Fix:** in the undo (and in the redo of a delete), call `selectProvider(null)` when the selected id is the one removed.

- **[bug]** `src/renderer/components/contacts/ContactForm.tsx:164-170,197-198`: when saving a contact fails, the form closes as if it saved. `createProvider` catches the error and returns `null` without a toast, and `updateProvider` logs and returns. `handleSave` then calls `onSaved()` and `onClose()`, so the typed details are lost with no message. This applies to the first contact too. `createCategory` in `CategoryManager.tsx:62` fails just as silently and clears the name box. **Fix:** have the store return success or failure (or rethrow). On failure, keep the form open and show "We couldn't save the contact — try again".

- **[bug]** `src/renderer/views/TemplateManagerView.tsx:85-98,128-131`: the page loads `grids` into local state once, on mount, and never again. Applying a template as a new list (`ImportPreviewModal`/`SetupTemplateCard` → `reloadAfterApply`) updates the grid store but not this local copy. Lists made from the sidebar while the page is open are missed the same way. Scenario with no lists: apply a .pulse template, then click "Save a list as template". It says "There's no list to save yet. Make one first." The new list is also missing from the "apply to existing list" choices and from the checklist template list picker. **Fix:** read `grids` from `useGridStore` instead of the local fetch.

- **[bug]** `src/renderer/components/reports/ReportBuilder.tsx:227` / `src/renderer/views/ReportsView.tsx:96`: Reports with no lists. "New report" opens the builder with an empty list picker, and the preview says "Working…" forever, because `fields` never loads. Save, Pin and Export do nothing, because `save()` returns null when `gridId === null`, with no message. **Fix:** when `grids.length === 0`, show an empty state on the Reports page ("Reports count what's in a list — make one first") with a button to the list setup, instead of the builder.

- **[visible]** `src/renderer/stores/gridStore.ts:121-135` (vs `:266`): the first tag added on a record page doesn't show in the list. `showTagsColumn` is only worked out in `loadGrid` ("shown when any record has tags", G-37). Going back to the list runs `refreshRows`, which refreshes `rowTagsMap` but not `showTagsColumn`. So a list that had no tags keeps the Tags column hidden until you switch lists or restart. **Fix:** in `refreshRows`, when the tags-column setting is unset, set `showTagsColumn` to true once `rowTagsMap.size > 0`. Or have `ProfileHeader.createAndAssignTag`/`toggleTag` (`ProfileHeader.tsx:191,213`) turn it on.

- **[visible]** `src/renderer/views/DashboardView.tsx:525-540`: a search with no matches in "What's due" shows the empty-dashboard messages. With records it says "All clear! No deadlines, tasks, or follow-ups need attention right now." With no records it says "Nothing here yet" and offers sample data. `filteredItems` already applies `debouncedSearch`, but the empty branch never checks it. **Fix:** check `debouncedSearch` first and show "Nothing matches "<query>"" (as the archived tab does).

- **[visible]** `src/renderer/views/TrashView.tsx:132,172` + `src/renderer/components/shared/TrashFiles.tsx:24`: when the only thing in the Trash is removed files, the page shows "Trash is empty" with the Files list right under it, and the "Empty Trash" button is hidden. Also, Empty Trash purges records, and their attachments cascade away, but it sends no `ATTACHMENTS_CHANGED`. `TrashFiles` keeps listing files that no longer exist, and Restore on them fails. **Fix:** have `TrashFiles` report its count (or lift its state) so the empty state and Empty Trash count files too. After `emptyTrash`/`purgeRow`/`purgeList`, reload the files.

- **[visible]** `src/renderer/components/grid/DataGrid.tsx:753` → `GridLoadingState.tsx:37`: hiding every visible column (any column, including the name column, can be hidden from its header menu) shows "No columns yet. Add a column to get started.". The list still has its columns. They're just hidden. That screen also has no button. **Fix:** when `hiddenColumns.length > 0`, say "All columns are hidden" with a "Show columns" button. In the truly empty case, add an "Add column" button. Today that action is only in the toolbar's More menu.

- **[visible]** `src/renderer/components/profile/CaseLog.tsx:849-852`: with "Show:" set to "Changes only" or one note type that has no entries, the timeline says "No <notes> yet." even when the record has plenty of notes. **Fix:** when `show !== 'notes'`, say "Nothing of this kind yet" or "No <notes> match what's shown".

- **[polish]** `src/renderer/components/layout/Sidebar.tsx:443`: deleting the open list always goes to the Dashboard. When it was the last list, people never see the "Bring back "<name>" from the Trash" option R5 added to the empty-lists screen (`GridView.tsx:137`). They land on "Nothing here yet / See an example" instead. **Fix:** after deleting, go to `/grid` (it opens the next list, or shows the empty screen with the Trash link).

- **[polish]** `src/renderer/views/LetterTemplateView.tsx:84-97,186`: a new template isn't selected after it's created; the previous one stays open. With no templates at all, the right pane still says "Select a template to view it". **Fix:** select the id that `LETTER_TEMPLATE_CREATE` returns after `load()`, and hide the right-pane hint when `templates.length === 0`.

- **[polish]** `src/renderer/components/documents/BatchDocumentsDialog.tsx:185`: the empty state says "Make one under Letters & documents". The sidebar item is "Letters" (that rename is deferred), so the place it names doesn't exist. **Fix:** say "under Letters" (as `RecordLetterDialog.tsx:94` does) until the rename lands.

- **[polish]** `src/renderer/views/DashboardView.tsx:87,331-333,541-546`: dead code. `const [filterTab] = useState('all')` is never set, so the `filterTab === 'overdue'` branch in `filteredItems` and the "Nothing overdue" branch of the Priority List empty state can't run. **Fix:** remove `filterTab` and those branches.
