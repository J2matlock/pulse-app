# S7: App shell, lock/unlock, shortcuts, dialogs, lifecycle

- **[bug]** `src/renderer/components/shared/ConfirmDialog.tsx:68`: the panel's `onKeyDown` runs `onConfirm()` on **any** Enter inside the dialog, whatever has focus. Say someone tabs to **Cancel** (or the X) on "Delete this list?" and presses Enter: the delete runs, because the Enter handler fires before the button's own click. This dialog is used in 25 places, most of them destructive. Fix: only confirm on Enter when the focused element is the typed-phrase input or the confirm button (`if (e.target !== inputRef.current && e.target !== primaryRef.current) return`), or drop the Enter shortcut and let the focused button handle it.

- **[bug]** `src/main/index.ts:392` (also `src/main/ipc/ipc-auth.ts:161`): `before-quit` always calls `runAutoBackup()`, even when the app is locked. With the database closed, `createAtomicDbSnapshot` throws "Database is not open" and `runAutoBackup` calls `recordAutoBackupFailure(...)`. `before-quit` then records it a second time. So every quit from the locked state shows "The last automatic backup failed…" in Settings → Backup on the next unlock. Common cases: auto-lock and then closing the window at the end of the day, and **every** tray "Quit", since closing to the tray always locks. The lock backup had already succeeded. Pressing Ctrl+L on the lock screen does the same thing through `AUTH_LOCK` → `runAutoBackupOnLock()` once the 1-hour gap has passed. Fix: skip the quit/lock backup when `!isUnlocked()`, as `closeToTray` already does.

- **[bug]** `src/main/index.ts:98-103` + `src/renderer/stores/settingsStore.ts:111`: pending edits aren't saved before a forced lock or a quit.
  - `forceLock` (sleep, screen lock, close-to-tray, the main-process inactivity fallback) closes the database first and only then sends `AUTH_FORCE_LOCK`. The renderer's `app:locking` flush (ScratchPad) then fails: the user gets a "We couldn't save your last scratch pad changes" toast on the lock screen, and the text is gone.
  - Quitting sends the renderer nothing, so scratch-pad text typed in the last 2 s, or a grid cell still being edited, is lost silently.
  - Even a normal Ctrl+L/auto-lock only flushes the ScratchPad. An open cell editor is unmounted after `AUTH_LOCK` has already closed the database, so its value is dropped.
  - Fix: have main send a "locking/quitting" message and wait briefly (e.g. ≤1 s) for an ack before closing the database. In `lock()`, blur `document.activeElement` (which commits cell editors) before `AUTH_LOCK`.

- **[bug]** `src/renderer/App.tsx:115-117`: `useGlobalKeyboard` and `useZoom` are registered before the auth early-returns, so they fire on the lock screen, password setup, setup and the forced recovery-reset screen.
  - Ctrl+K, `?`, Ctrl+Shift+T and Ctrl+Shift+F set palette/shortcuts/task-dialog/focus-mode state while locked, and those pop open right after unlock.
  - Ctrl+N (with focus off the password box) calls `addRow()` with the stale `activeGridId`. While locked that gives a "Could not add…" toast. During the recovery reset, when the database is open, it actually creates a blank record.
  - Ctrl+=/−/0 change the zoom on the lock screen, but `SETTINGS_UPDATE` fails (database closed), so the change isn't saved.
  - Fix: early-return from the handlers unless `authState === 'ready'` (pass it in, or read `isLocked`/`recoverySession` from the store).

- **[bug]** `src/renderer/components/shared/MorningBriefing.tsx:120,124`: unticking "Show this summary the first time I unlock each day" is only saved by `close()` (the X or a backdrop click). "Start Focus Mode" and "Open dashboard", the two main buttons, call `setBriefing(null)` directly, so the opt-out is ignored and the briefing comes back tomorrow. Fix: route both buttons through a shared helper that saves `briefing_enabled=false` when `!keepShowing`.

- **[visible]** `src/renderer/components/shared/MorningBriefing.tsx:87`: the briefing is `aria-modal`, but it has no Escape handler, no initial focus and no focus trap. Escape does nothing, and Tab walks into the page behind it. The label text is `text-sm` (14px). Fix: add `useFocusTrap` plus a keydown Escape handler that calls `close()`, and make the label `text-base`.

- **[visible]** `src/renderer/App.tsx:294-304` + `CommandPalette.tsx:257`: Focus mode is `z-[200]` and rendered last, and nothing stops global shortcuts while it's open.
  - Ctrl+K opens the palette (`z-[100]`) **behind** Focus mode. Its input still autofocuses, so typing and Enter go to an invisible palette.
  - `?` opens KeyboardShortcutsModal (also `z-[200]`, but earlier in the DOM), which is hidden too and grabs focus through its focus trap.
  - Ctrl+Shift+T opens TaskFormDialog (`z-50`), also hidden.
  - While any of these is open, Escape no longer closes Focus mode, because its handler sees two `aria-modal` elements.
  - Fix: render these overlays above Focus mode (z ≥ 210), or ignore those shortcuts while `focusModeOpen`.

- **[bug]** `src/renderer/components/shared/KeyboardShortcutsModal.tsx:44`, `WhatsNewModal.tsx:109`: the record page closes on Escape, and these two modals close on Escape too, through React `onKeyDown` without `preventDefault()`. React commits the close in a microtask, which runs before ProfileView's `window` keydown listener. By the time `escapeBelongsElsewhere` checks, the modal is gone and `defaultPrevented` is false, so Escape also leaves the record page. Example: on a record, press `?` and then Escape, and you're sent back to the list. jsdom tests miss this because they have no microtask checkpoint between listeners. Fix: call `e.preventDefault()` in these (and any other React-handled) Escape closers. `escapeBelongsElsewhere` already honours it.

- **[visible]** `src/renderer/App.tsx:294`: the overlay `<ErrorBoundary fallback={<></>}>` wraps the command palette, UndoToast, MorningBriefing, WhatsNew, the tours, GlobalTaskDialog, ImportPreviewModal **and** FocusModeView. One render error in Focus mode (the biggest of them) silently removes every overlay for the rest of the session: no Ctrl+K, no undo toasts, no import preview. `focusModeOpen` also stays true. Nothing resets it until lock/unlock. Fix: give FocusModeView (and the import/starter dialogs) their own boundary that closes them and shows a toast, and reset the boundary when its children change.

- **[visible]** `src/renderer/components/shared/ErrorBoundary.tsx:48` + `App.tsx:179`: the route boundary sits outside `MainLayout`, so a page crash also takes the sidebar and top bar. The only way out is "Go back to the start", which goes to `#/` → `/grid`. If GridView is the page that crashes (bad cell data, say), the user is stuck in a loop. Even after a relaunch the app opens on the grid again. The boundary also shows the raw `error.message` in `text-sm`. Fix: wrap `children` inside `MainLayout` with a boundary keyed on `location.pathname`, offer "Open the dashboard" as well, and show a plain sentence instead of the raw message.

- **[visible]** `src/main/index.ts:152,162`: the window is restored from saved state without checks.
  - `saveWindowState` stores `getBounds()` even when maximized. On the next launch the "normal" size is the whole screen, so un-maximizing does nothing visible.
  - The saved `x`/`y` are reapplied without checking that they're still on a connected display. A laptop that was used with an external monitor opens Pulse off-screen.
  - Fix: save `getNormalBounds()`. On launch, drop `x`/`y` unless the rectangle intersects one of `screen.getAllDisplays()` work areas.

- **[polish]** `src/renderer/hooks/useBackupReminder.ts:33,40`: the recovery-key re-offer (F-32) is only reached when an offsite backup is overdue, after the early returns for `scheduled.overdue` and `!offsiteOverdue`. A user without a recovery key who keeps backups current, and who has dismissed the Getting-started card, is never reminded. When it does fire, it stacks right on top of the backup toast. Fix: call `checkRecoveryKeyReminder` independently of the backup branches (e.g. from `useAuthGating` after `checkBackupReminder`).

- **[polish]** `src/renderer/components/layout/MainLayout.tsx:48`: the comment says the update check runs "once on launch". But MainLayout lives inside the HashRouter tree, which unmounts on every lock, so the GitHub request runs again on **every unlock**. The sidebar's collapsed state also resets on each unlock. Fix: keep an "update checked" flag at module level (or in a store), and keep `sidebarCollapsed` in the settings store.

- **[polish]** `src/renderer/hooks/useZoom.ts:16`: zoom-in only matches `e.key === '='`, so Ctrl+NumpadPlus and Ctrl+Shift+= (`'+'`) do nothing, while Ctrl+NumpadMinus does zoom out. Fix: accept `'+'` as well.
