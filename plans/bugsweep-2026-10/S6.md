# S6 — Contacts, snippets, letters, forms, templates, attachments

Read-only review. Each item was traced end to end in the code. Not repeated here: the R1–R7/V1 polish findings and the deferred items in progress.md (the ContactFilterBar timer race, vocabulary leaks in plain screen text).

## Contacts

- **[bug]** `src/main/ipc/ipc-contacts.ts:297-299` (with `src/main/contacts.ts:178-184`): **"Export All Contacts" writes vCards with most fields missing.** The export-all path (`ContactImportExport.tsx:155` sends `null`) calls `getProviders({})`. That is the list query, which selects only name, org, title, phone_main and email. So every exported card loses its direct, cell, fax and after-hours phones, website, address and notes, and silently stops at 1,000 contacts (`LIMIT 1000`). Exporting a single contact works, because that path uses `getProvidersByIds` (`p.*`). Fix: when the argument is `null`, load full rows (for example `SELECT id FROM providers`, then `getProvidersByIds` in chunks).
- **[bug]** `src/main/contacts-vcard.ts:182-251` and `:120-131`: **a Pulse → vCard → Pulse round trip loses the category, every custom field and the after-hours phone.**
  - `emitVCard` never writes `CATEGORIES`, even though import reads it (`ipc-contacts.ts:212-227`).
  - Restoring custom values needs `provider.category_id` (`ipc-contacts.ts:277`). With no category, every `X-PULSE-FIELD-*` line is dropped too.
  - After-hours is written as `TEL;TYPE=PAGER`. On import, PAGER falls into the `WORK || !phone_main` branch, so it's dropped when a main phone exists, or becomes the *main* phone when none does.
  - "Direct" is written as `TYPE=HOME`, so other apps show a work line as a home number.

  Fix: emit `CATEGORIES:<name>`, and map after-hours to something import reads back (e.g. `TYPE=X-AFTER-HOURS`, handled before the WORK fallback).
- **[bug]** `src/main/contacts-vcard.ts:13-19, 94-104`: **vCard import mangles common real-world files.**
  - **Accented names come in as gibberish.** vCard 2.1 files from Android and Outlook encode non-ASCII as `FN;CHARSET=UTF-8;ENCODING=QUOTED-PRINTABLE:Jos=C3=A9`. Pulse doesn't decode quoted-printable or join its soft line breaks (`=` at the end of a line), so the name imports as "Jos=C3=A9".
  - **Apple Contacts' grouped lines are dropped.** Lines like `item1.EMAIL`, `item1.TEL` and `item2.ADR` keep the `item1.` prefix as part of the property name, so nothing matches.
  - **Backslashes are unescaped in the wrong order.** `\\n` becomes a newline, so a note containing `C:\new` comes back broken.

  Fix: strip a `group.` prefix, decode QUOTED-PRINTABLE (joining lines that end in `=` first), and unescape in a single pass (`/\\([\\,;nN])/g`).
- **[visible]** `src/renderer/components/contacts/ContactImportExport.tsx:155-161` and `src/main/ipc/ipc-contacts.ts:235`:
  - Cancelling the Save dialog still shows "Export complete! Your contacts have been saved." The handler returns `ok(null)` on cancel, and the component sets `exportDone` for any ok result.
  - A file with 501–1,000 contacts parses fine (`parseVCard` caps at 1,000), shows them all selected, then fails at import with "Import limited to 500 contacts at a time". Nothing tells the person to untick some.

  Fix: treat `res.data === null` as cancelled. Either import in chunks of 500, or cap the preview with an explanation.
- **[bug]** `src/renderer/stores/contactsStore.ts:212-247` and `:169-190`: **undoing a contact delete or edit loses data.**
  - Both snapshots come from `get().providers`, the list rows, which lack phone_direct, cell, fax, after-hours, website, address, hours, languages, referral process, availability notes, notes and tags.
  - Undo of delete brings the contact back without any of those. Tags are lost too (`provider.tags` is undefined on list rows), and custom field values are never restored at all.
  - Undo of an edit builds `prevValues` with `undefined` for those fields, and `updateProvider` skips undefined. So undoing an address, notes or cell-phone change does nothing while reporting success.
  - Redo-of-create makes a new id, but undo still deletes the old `created.id`.

  Fix: snapshot from `selectedProvider` or a fresh `CONTACTS_GET_ONE` plus `CONTACTS_GET_CUSTOM_VALUES`, use explicit `null`s for empty fields, and track the current id in create undo/redo.
- **[bug]** `src/renderer/views/ContactsView.tsx:97-124` with `src/renderer/components/contacts/ContactDetail.tsx:371-379`: **the delete confirmation can delete a different contact.**
  - The window keydown handler only skips inputs, so arrow keys, `n` and `e` still act while a ConfirmDialog has focus on its buttons. `ConfirmDialog` stops only Escape and Enter.
  - Scenario: click Delete on contact A, then press ↓. `selectProvider` moves to B, but `ContactDetail` isn't keyed by provider, so the open dialog now reads "delete B". Enter deletes B.
  - ↑/↓ also steal arrow-key scrolling inside the detail panel (its tab panel has `tabIndex=0`).

  Fix: ignore the shortcuts when focus is inside `[role=dialog]` or the detail panel, and key `ContactDetail` by `provider.id`.
- **[bug]** `src/renderer/views/ContactsView.tsx:128-133`: **Ctrl/⌘+C is hijacked on the Contacts page.** After clicking a contact (`focusedIndex >= 0`), copying selected text from the detail panel (an address, a note, a log entry) calls `preventDefault`. It copies the main phone instead, or nothing at all when there is no main phone. Fix: only take over the shortcut when `window.getSelection()` is empty and focus is on the list row.
- **[bug]** `src/main/contacts-categories.ts:56-62`: **deleting the last category brings back all 10 defaults.** `getCategories()` re-seeds whenever the table is empty in a human-services workspace. `deleteCategory` then reloads categories, so the 10 defaults reappear at once and can never be cleared. Fix: guard the seeding with an `app_meta` flag, as `getLetterTemplates` does (`templates.ts:681-686`).
- **[bug]** `src/renderer/stores/contactsStore.ts:364-369`, `src/renderer/components/contacts/CategoryManager.tsx:131-137` and `src/main/export-pdf.ts:722-724`: **category colours and names go stale or break printing.**
  - **Stale chips.** Renaming or recolouring a category reloads only `categories`. Contact cards, rows and the open detail keep the old `category_name`/`category_color` (joined values) until the page is left.
  - **Hand-typed colours break printing.** The edit row has a free-text colour box with no check, so `red` or `#abc` can be saved. The directory PDF then parses it with `parseInt(slice)` into NaN, and jsPDF throws ("Invalid argument passed to jsPDF.f2"), so Print fails. Cards also render `red20` as an invalid background.

  Fix: reload providers (and the selected provider) after a category update, and accept only `#rrggbb` (or normalise the colour) in both IPC and UI.
- **[bug]** `src/renderer/components/contacts/ContactForm.tsx:162-168` with `contactsStore.ts:146-172`: **a failed save closes the form as if it worked.**
  - The store's `createProvider` catches every error and returns `null`; `updateProvider` catches and returns. The form then calls `onSaved()`/`onClose()` anyway.
  - Any failure other than read-only (validation, a database error) throws the typed contact away with no message.

  Fix: let the store rethrow (or return a success flag) so the form keeps its contents and shows its existing "We couldn't save" toast.
- **[visible]** `src/renderer/components/contacts/ContactForm.tsx:178-195` and `contactsStore.ts:376-388`: **tags show wrong after editing.**
  - Tags changed in the Edit form are synced *after* `updateProvider` has already re-fetched `selectedProvider`. The detail panel keeps showing the old tags until you click another contact.
  - In the detail panel, adding a tag that already exists appends a duplicate chip; the server does `INSERT OR IGNORE`, and React gets a duplicate key. Undo of that add then removes the *original* tag.

  Fix: call `selectProvider(id)` after the tag sync, and skip `addTag` when the tag is already present.
- **[visible]** `src/renderer/components/contacts/ContactInteractionLog.tsx:225` and `:131`: **the Log tab overflows and hides its row actions.**
  - The seven type buttons (icon + label, `px-3`, about 640px) sit in a non-wrapping `flex` inside the fixed 420px detail panel (about 350px usable). "Meeting", "Referral" and "Other" are off-screen behind a horizontal scrollbar.
  - Each entry's Edit/Delete wrapper is `opacity-0 group-hover:opacity-100`. The buttons' own `focus:opacity-100` can't override a transparent parent, so keyboard users tab onto invisible buttons.

  Fix: `flex-wrap` (or icon-only buttons with labels on narrow widths), and `group-focus-within:opacity-100` on the wrapper.
- **[polish]** `src/main/export-pdf.ts:514-523, 546`, `export-pdf.ts:705-708` and `src/renderer/components/profile/LinkedProviders.tsx:381`: **availability shows three ways, and long details run off the contact PDF.**
  - The app says "Not Accepting". The contact PDF prints the raw key ("full", "accepting"), and the directory PDF and the record page print "Full".
  - The contact PDF's `kv()` writes values on one line with no wrapping, so a long address, availability note, hours or custom value runs off the right edge.

  Fix: share the `AvailabilityBadge` labels, and use `splitTextToSize` in `kv()`.

## Snippets

- **[bug]** `src/main/ipc/ipc-tasks.ts:331-336`: **deleted built-in snippets come back.** `SNIPPET_GET_ALL` re-seeds the 12 built-ins whenever the table is empty in a human-services workspace. Someone who deletes all snippets (to start fresh, or after deleting the built-ins) gets all 12 back the next time Snippets or a record page loads. Fix: an `app_meta` "snippets_seeded" flag, like letter templates.
- **[bug]** `src/renderer/utils/snippetExpander.ts:68-76` with `ipc-tasks.ts:356`: **an exact trigger can lose to a longer one.** Matches are prefix matches in server order (`ORDER BY category, trigger_text`), and Tab expands the first. With `/ref` (category Admin) and `/re` (category Visit), typing `/re` + Tab inserts the `/ref` text, because Admin sorts before Visit. Fix: in `matchSnippets`, put the exact match first, then shorter triggers, then the rest.

## Letters and placeholders

- **[bug]** `src/main/placeholders.ts:77-89`: **the legacy `{{dob}}`, `{{age}}` and `{{medicaid_cin}}` are filled from the wrong columns.**
  - These come from substring matches on column names, with the last match winning.
  - A "Birth certificate received" checkbox after "Date of birth" makes `{{dob}}` print "Yes". The built-in "Referral Request" and "Status Update" letters use `{{dob}}`.
  - Any column containing "cin" ("Vaccine date", "Medicine", "Principal") overwrites `{{medicaid_cin}}`.

  Fix: prefer date columns for dob/age, don't overwrite a value already set, and match `cin` only as a whole word (`/\bcin\b/`).
- **[bug]** `src/main/placeholders.ts:124-126, 172`: **"Insert field" offers columns that always print blank.**
  - Its "Columns" group lists every visible column. But link columns, file-count columns and computed columns (Age from DOB, days-since) have no row in `cells`; they're computed in the grid query or in the window.
  - So `{{field:Age}}`, `{{field:Files}}` and `{{field:<link column>}}` resolve to `''`. They aren't reported as unknown, so the letter silently has a gap.

  Fix: compute these in `resolvePlaceholders` (link via `linkSelectSql`-style query, age from its source column, file count from `attachments`) or leave them out of the menu.
- **[bug]** `src/main/placeholders.ts:136-138` (offered at `:183-184`): **some offered `{{linked:…}}` fields never fill.** `{{linked:Owner.<column>}}` splits on the *last* dot, so any linked column whose name contains or ends with a dot ("D.O.B.", "Policy No.") never resolves, even though the menu offers exactly that key. Fix: match the label against the known link labels as a prefix instead of splitting on `lastIndexOf('.')`.
- **[visible]** `src/main/placeholders.ts:27-39`, `src/main/export-forms.ts:42-48` and `src/renderer/components/forms/FillFormDialog.tsx:224`: **Tags columns show as raw JSON.** Tags are stored as a JSON array.
  - `{{field:Tags}}` in a letter and a printed filled form both show `["urgent","spanish"]`.
  - The fill-in form prefills its text box with that JSON.
  - On a new record, the form saves typed `a, b` as plain text, not as a JSON array.

  Fix: add a `tag` case (join with ", ") to `formatValue` and the form-print `value()`, and give the form a comma-separated tag input that saves `JSON.stringify(tags)`.
- **[bug]** `src/renderer/components/documents/BatchDocumentsDialog.tsx:42-46, 52-56`: **choosing another list in "Print documents or labels" from the Letters page breaks the dialog.**
  - Columns come from `useGridStore` (the *open* list) filtered by `grid_id`. Opened from the Letters page (`pickList`), choosing any other list gives no columns.
  - "Address labels" then says "This list has no address column", and the "deadline due between" choice disappears.
  - `addressCol`/`deadlineCol` keep the previous list's column ids. "Make PDF" stays enabled and fails with "Choose the column with the address."

  Fix: load the chosen list's columns (`GRID_GET` or a columns IPC) when `gridId` changes, and reset `addressCol`/`deadlineCol`.
- **[visible]** `src/renderer/views/letter-template/GenerateLetterModal.tsx:60-74`: **people with the same first name can't be told apart.** The record picker labels each row with the name-column cell only, not `getClientName()`. In lists with a last-name column or a display format, two "Maria"s look identical. With no name column it falls back to the jargon "Row 12". Fix: use `getClientName(row, columns)` (as the profile header now does), and `t('record')` for the fallback.
- **[visible]** `src/main/export-pdf.ts:38-66` (all jsPDF exports): **PDFs garble characters outside Western European.**
  - Every PDF uses the built-in Helvetica (WinAnsi only). Names and text such as "Nguyễn", "Łukasz", "Ольга" or Chinese come out garbled in letter, batch, form, contact and directory PDFs.
  - The single-letter PDF is also A4 (`format: 'a4'`), while batch letters and forms are US Letter.
  - Save-dialog default names drop non-ASCII letters (`ipc-contacts.ts:307`, `ipc-export.ts:412`). "José Núñez" becomes "Jos Nez.vcf", and an all-Cyrillic name gives ".vcf".

  Fix: embed a Unicode TTF (e.g. Noto Sans) once in `export-shared`, use `format: 'letter'` (or a setting) for single letters, and keep Unicode letters in file names (strip only `\/:*?"<>|`).

## Forms

- **[bug]** `src/main/export-forms.ts:98-126`: **on printed forms, a half-width field followed by a full-width one prints on top of each other.** After the first half field, `halfOpen` is true and `y` is reset to its label line. The next field (full width, or a half-width dropdown or notes field that is forced to full) starts at that same `y` and `x = margin`, overwriting the label and line. Only sections and notes close an open half row. Fix: at the top of the column branch, `if (halfOpen && !half) { y += 15; halfOpen = false }`.
- **[visible]** `src/main/export-forms.ts:68`: **"Print filled" cuts long answers to one line.** `writeLine` prints only `splitTextToSize(text, w)[0]`. A long text, phone-list or email answer is cut to one line with no ellipsis, and the signer never sees the rest. Fix: print every wrapped line (adding writing lines as needed), as the notes/address branch already does.
- **[bug]** `src/renderer/components/forms/FormBuilder.tsx:110` with `src/main/forms.ts:138` and `FillFormDialog.tsx:135,269`: **"Required" can't be switched off for a column the list marks required.**
  - Unticking stores `required: undefined`, and both fill and submit use `f.required ?? column.required`, so the question stays required.
  - The builder also shows those questions unticked when they *are* required (e.g. a column made required after the form was built).

  Fix: store `required: false` explicitly when unticked, and initialise the tick from `f.required ?? requiredByColumn(c)`. Or show it ticked and locked, with "Required by the column".
- **[bug]** `src/renderer/components/forms/FormsDialog.tsx:48`: **a stray click outside throws away a form being built.** The backdrop's `onClick={onClose}` closes the whole dialog while the builder is open, discarding every field added, with no question. FillFormDialog guards this (1.37); the builder doesn't. Fix: ignore backdrop clicks while `editing` (or ask first when the builder is dirty).

## Attachments

- **[visible]** `src/main/attachments.ts:159` with `src/main/ipc/ipc-attachments.ts:128`: **renaming a file can strip its extension.** Renaming "scan.pdf" to "Intake scan" stores it without the extension. "Save a copy" then offers "Intake scan" with no filter, so the saved file has no extension and the system can't open it by double-click. Fix: keep the original extension when the new name has none (or append it in the save dialog's `defaultPath`).
- **[polish]** `src/main/ipc/ipc-attachments.ts:50-51`: **"Attach again" can hide files that were already added.** When some dropped files are new and some are duplicates, the new ones are committed in the first call. If the second "Attach again" call then fails (for example over the storage limit), the handler returns that failure without `announce(rowId)`. The record's Files list and timeline don't show the files that *were* added, while the toast says it failed. Fix: announce when `first.data.added.length > 0` even if the second call fails, and mention them in the message.

## Checklist and list templates

- **[polish]** `src/renderer/views/TemplateManagerView.tsx:136`: **the picker starts on the wrong list.** "Save this list as a template" preselects `grids.find(g => g.is_active === 1)`, which is always the first list because `GRID_GET_ALL` returns only active lists. It should be the list that is open. Fix: default to `useGridStore.getState().activeGridId` when it's in `grids`.
